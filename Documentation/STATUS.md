# APEX Formula: status

Last updated: 2026-11-12

## Verified (this machine, UE 5.8.4, Xcode 27.2, Mac)
- Mac editor target `APEXFormulaEditor` compiles.
- 6 automation tests pass (`APEX.*`): lap counting (3 valid laps), cut-course invalidates a lap, acceleration and
  braking, downforce = 0.5*rho*v^2*A*C (and 4x at 2x speed), lateral accel is grip-limited, track centreline closed
  with minimum corner radius >= 80 m.
- Headless auto-drive (`-game -nullrhi -APEXAutoDrive`, empty `/Engine/Maps/Entry`, fixed 60 Hz):
  3 valid laps of the 3003 m procedural circuit, lap times 36.37 / 35.90 / 35.90 s, then clean exit.

Run it:
```
~/unreal/UE_5.8/Engine/Binaries/Mac/UnrealEditor-Cmd ~/Development/APEXFormula/APEXFormula.uproject \
  "/Engine/Maps/Entry?game=/Script/APEXFormula.APEXFormulaGameMode" -game -nullrhi -nosound -unattended \
  -APEXAutoDrive -benchmark -fps=60 -stdout
```

## Pace and art pass (2026-11-12)
- Pace: new designed 3,508 m circuit (start straight, hairpin 23 m radius, chicane, sweeper), drag CdA 1.45 so top speed
  settles at ~331 km/h (not the clamp). Auto-driver plans speed from track curvature. Three laps: 59.6 / 57.0 / 57.0 s,
  avg ~222 km/h, slowest corner ~131 km/h (sampled). 0-100 km/h and 0-200 km/h are tested to be in a believable range.
- Art, all generated by scripts in `Blender/` and imported by `Python/ue_import.py` (rerun both to rebuild):
  `gen_car.py` (original open-wheel car, 5.68 x 2.01 x 1.06 m, ~2.2k tris + separate wheel), `gen_textures.py`
  (asphalt, grass, kerb, barrier, facades, seats), `gen_track.py` (road, kerbs, barriers, start line, grass from the
  same centreline as the game), `gen_scenery.py` (pine, oak, 4 buildings, grandstand).
  Game: car + 4 spinning wheels (fronts steer), Blender track mesh (old cubes kept as invisible collision), ~2,350 trees,
  ~94 buildings, 4 grandstands, placed by seeded rules away from the track.
- Pipeline gotchas found and fixed: materials on instanced meshes need `used_with_instanced_static_meshes` or the engine
  silently uses the default material (trees rendered black); UVs must be set before flipping a bmesh face; FBX import
  flips Y; runtime-created components default to Static mobility.
- Car detail pass (2026-11-12): 4,002 vertices / 3,364 polys (was 934). Glossy metallic red paint with a white centre
  stripe and dark carbon underbody band (livery is geometry-driven: faces reassigned to slots by position), carbon twill
  texture on carbon parts (box-projected UVs), race number "27" roundel (nose + airbox sides) and fictional "APEX"
  wordmark (sidepods, rear wing) as shrink-wrapped masked decals, tyres with moulded sidewall + red compound ring,
  5-spoke rims, 4-element front wing with cascades, bargeboards, sidepod louvres, shark fin, exhaust, DRS gap.
  Screenshots: `Documentation/screenshots/{car_front,car_rear,car_side,gameplay}.png`. Debug flags for more:
  `-APEXHero -APEXHeroYaw=<deg> -APEXHeroPitch=<deg> -APEXHeroDist=<cm> -APEXNoHUD -APEXShot -APEXShotTime=<s>`.
- HONEST LIMITS: still stylised low-poly art, not the look of a studio PlayStation game. The car has no normal maps,
  no real reflections (default sky reflection only), no brake discs or visible suspension detail inside the wheels, no
  tyre wear/dirt, a single livery, and chunky box wing endplates. Trees are simple low-poly. No crowd figures, no pit
  buildings, no billboards, no road rubber marks, no weather. The "27" and "APEX" decals are 3 mm above the surface and
  may shimmer at long distance. Triangle counts and the 2,350 shadow-casting instances are untested on iPhone; the
  mobile renderer and desktop sky will likely need LODs, fewer instances and a cheaper sky there. Clear-coat paint was
  not used because mobile support is unverified.

## Touch controls and HUD (added 2026-11-12)
- 12 `APEX.*` tests pass (6 new input/UI tests: layout fits safe area and never overlaps for both handednesses and
  UI scale 0.6-1.6, dead zone/sensitivity, buttons, virtual wheel, tilt, style cycling, lap-time format).
- Rendered on this Mac (Metal, 1280x720 window): HUD, controls, minimap and chase camera draw correctly.
  Screenshot: `Saved/Screenshots/MacEditor/HighresScreenshot00000.png` (run with `-APEXAutoDrive -APEXShot`, no `-nullrhi`).
- Styles: Buttons, Virtual Wheel, Tilt; tap the top-centre button to cycle. Settings on `UFormulaMobileInputComponent`:
  sensitivity, dead zone, left-handed, UI scale, tilt angle, wheel lock.
- UNVERIFIED (needs an iPhone): real touch events, the tilt axis (`GravityVec.Y` is a guess for landscape),
  `FDisplayMetrics::TitleSafePaddingSize` units/values on a notched phone, and hiding Unreal's default touch interface.
  On Mac only the keyboard is used; touch has been tested through the component API, not a screen.
- No haptics, no left-handed toggle in the UI (it is a component property), no gear/camera/pause/pit buttons.

## Implemented
- `AFormulaTrack`: procedural closed circuit (instanced cubes: road, barriers, ground), centreline, 8 checkpoints, start slot.
- `AFormulaVehiclePawn`: grip-limited bicycle model, chase camera, barrier collision, keyboard input (WASD/arrows),
  pure-pursuit auto-driver for verification, on-screen debug line (speed, downforce, lap, time).
- `AAPEXFormulaGameMode`: builds track, start slot and lights at world init when the map has no track.
- `UFormulaLapTimingComponent`: ordered-checkpoint lap validation.

## Known issues / not yet true
- Environment (fixed 2026-11-12): sky atmosphere + atmosphere sun + real-time-capture sky light + light fog +
  unbound post-process volume with MANUAL exposure (bias 9.5). Tuned on Mac/Metal by screenshot: 8.5 too dark in
  shadow, 11.5 washed out, 14.5 pure white. Override without rebuilding: `-APEXExposure=<value>`.
  NOT checked on iPhone: Sky Atmosphere and real-time sky capture are desktop-class features. The mobile renderer may
  not support them, so expect to need a cheaper sky there (e.g. a sky-dome mesh) and a re-tuned exposure.
- Still plain: flat-colour primitives, no textures, no shadows tuning, no clouds, car is a grey box.
- Not seen on screen: the run was headless (NullRHI). Rendering, lighting and camera framing are unchecked.
- Not on an iPhone. iOS target fails: "Missing files required to build IOS targets. Enable IOS as an optional
  download component in the Epic Games Launcher." No device connected, no signing identities.
- Pace is too fast to be realistic: ~301 km/h lap average, 342 km/h peak (the 95 m/s cap) on a 3 km loop. Needs tuning.
  The auto-driver also has no cornering limit beyond its own speed target, so it says little about human drivability.
- No touch controls, no real HUD (UMG), no saved map asset, no Chaos Vehicles, no AI opponents.
- No FPS or memory measurements exist yet.
- The engine appended an `[/Script/AndroidFileServerEditor...]` block with a SecurityToken to `Config/DefaultEngine.ini`.
  It is local tooling config; remove it before sharing the repo.
- git-lfs not installed.
